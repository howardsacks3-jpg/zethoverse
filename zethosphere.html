05 / Response protocol

What happens when a threat is detected?

RED ALERT · Critical

Examples: unexpected minting, authority or program upgrade, suspicious treasury movement, vesting permission change or a confirmed compromise indicator. Planned response: immediate founder email, evidence links, affected assets and a step-by-step containment checklist.

WARNING · Investigate

Examples: unusual sales or volume, unexpected wallet activity, unexplained balance changes or missed monitoring checks. Planned response: investigate, verify independently and escalate if confirmed.

INFORMATION · Routine

Examples: normal verified transactions, successful checks and scheduled security summaries. Planned response: transparent public record and periodic report.

Security reality: ZETHOSPHERE is being designed to reduce risk through monitoring, early warning and a rehearsed response. It cannot guarantee that hacking will be prevented or reverse a finalized Solana transaction. Alerts must be verified before irreversible action.

Secure login not configured

Password-only login is the initial requirement; two-factor authentication is deferred. This static page does not collect or store passwords.

07 / Build status

What remains before this becomes operational

  • Confirm official ZETHO Mainnet mint and all project-controlled public addresses.
  • Build a server-side, read-only Solana and market-data monitor.
  • Implement transaction classification, anomaly rules and scan timestamps.
  • Build and test the private password-only founder authentication service.
  • Connect and test red-alert email delivery with the founder's chosen recipient.
  • Test simulated incidents and false-positive handling before enabling live alerts.
Wallet safety: The dashboard must never ask for a seed phrase, private key or wallet signature. Monitoring will use public blockchain data and read-only access. It will not create streams, change permissions, transfer tokens or automatically move funds.
